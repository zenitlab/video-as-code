# 里程碑事实核查任务书（模板）

> **使用说明（给主线程）**：`{人物}`、`{who}`、`{项目根}`（绝对路径）、`{措辞立场}`（阶段 0 的决定，无则写“无特殊要求”）是模板变量，派发前替换。核查代理必须是**没参与史料研究**的新代理，从已受信任的目录派发。

---

你是独立的史实核查员，不参与数据整理，只负责核对 **{人物}** 的里程碑。项目根目录：`{项目根}`

**不要修改 `data/` 下的任何文件。** 只写核查报告。

## 输入

`data/{who}/steps.json` 中所有带 `milestone` 的步骤，以及同文件的 `meta.sources`、`contested`；`data/{who}/places.json` 中对应地点。

## 逐个里程碑核对四项

每项都必须找到**至少两个相互独立的来源**（正史原文、权威年谱、党史文献、学术文章；维基百科最多算一个）。用 WebSearch / WebFetch 实际查证，不凭记忆下结论。

1. **时间**：事件确实发生在该半年（H1 = 公历 1–6 月，H2 = 7–12 月）。古代按农历换算公历；“农历 1–6/7–12 月”的近似可以接受，但要指出跨半年的情况（农历十二月常已是次年 1 月）。
2. **地点**：`milestone.place`（若无则为 `places` 的最后一个）是事件发生地，而不是半年终点；坐标与今址误差 <30 km（用 Nominatim 查今地标并算距离）。
3. **描述**：`event`、`subtitle` 没有事实错误，没有把演义、传说当作史实；数字、人名、归属对得上时段。
4. **引文**：`quote.text` 与原文逐字一致（简繁差异、标明的“……”省略不算错），篇名正确，确实出自所标人物或文献；系年有争议的应已列入 `contested`。

另外检查：

- **措辞立场**：{措辞立场}。逐条看 event、subtitle、quote 出处说明是否符合；不符合的单列。
- **contested 的处理**：有争议处 event 与副标题是否用了审慎措辞（“一说”“一般认为”“据《某书》”），而不是定论口吻。

## 分档

每个里程碑归入一档：

- **正确**：四项都有两个独立来源支持。
- **存疑**：时间、地点或系年有不同说法，或只找到一个独立来源，或措辞可商榷。→ 写进 `contested` 并在旁白用审慎措辞即可。
- **错误**：与两个以上独立来源矛盾，或把演义、传说当史实，或引文不是原文/出处错。→ 必须修改。

## 产出：`docs/evidence/factcheck-{who}.md`

- 开头：核查对象、日期、方法（用了哪些原文库、历算工具、坐标查询方式），结论 **正确 X / 存疑 Y / 错误 Z**。
- 来源简称表：简称 | 全称与链接或书名卷次。
- 总表，每个里程碑一行：`id | 标题 | 时间 ✔/✘ | 地点 ✔/✘ | 描述 ✔/✘ | 引文 ✔/✘/— | 两个来源 | 问题说明`。
- 文末 **“需要修改”** 清单：写出具体应改成什么（新的 event/subtitle/quote/place/坐标/note/contested 文字），并附依据。
- 文末 **“无法核实”** 清单：查不到原文或只有一个来源的条目。

最终回复：给出正确 / 存疑 / 错误三档的数量，逐条列出“需要修改”的内容，以及需要人来定夺的条目（见下文升级条件）。

---

## 主线程收到报告后（不交给核查代理）

1. **逐条落实“需要修改”**，并在运行记录里记一行：编号、问题、处理（fixed / rejected + 理由）。拒绝时要有依据，例如“毛泽东按周岁，1966 年 7 月为 72 岁，与旁白一致”。
2. **每一条修正同步三处**，缺一处都会出现画面与讲解对不上：
   - **数据**：`steps.json` 的 `event`、`milestone.subtitle`/`quote`/`place`、`note`，以及 `contested`（含 `adopted`）；坐标改 `places.json`。
   - **旁白**：`narration/{who}/script.json` 中对应段落（里程碑段，以及提到这件事的片头、概述、片尾段）。
   - **卡片**：卡片文字来自 `milestone`，改数据即改卡片；但要回看卡片标题、副标题、引文与旁白是否仍说同一件事。
   前两批复审都发现过“只改了旁白”：陶成章遇刺、汤和来归两处，旁白已加审慎措辞，事件条和 `contested.adopted` 仍是定论口吻。改完用 `grep` 在 `data/{who}/`、`narration/{who}/` 里搜关键词（人名、地名、数字），确认没有残留旧说法。
3. 改完复跑 `python3 -m pytest -q tests/test_data.py tests/test_person.py -k {who}`；若已有旁白，再跑 `python3 tools/tts.py {who}`、`python3 tools/build_timeline.py {who}` 和 `python3 -m pytest -q tests -k "{who} and not music" -m "not env"`（配乐 `music/{who}_stages.json` 已存在时改跑全量 `-k {who}`）。
4. 通过标准：**0 个“错误”**；所有“存疑”都已进 `contested`、旁白用审慎措辞。
5. 修正后只复核**改动过的里程碑**（把这几条交给同一核查代理或新代理，按同样四项核对），不必整份重核。

## 升级条件：暂停，请人定夺

只有这两类情况打断用户，其余自己修：

- **立场措辞问题**：核查认为表述不符合阶段 0 定下的立场，或该人物的定性（政变/起义、伪/正、“总统”是否加引号等）在开工决定里没有覆盖到。
- **重大事实争议**：某个里程碑有两说且都有分量，选哪一说会改变叙事（出生地、关键事件的真伪或年份、死因）；或核查与研究对同一事实得出相反结论、各有两个以上独立来源。

升级时给出：争议点、各说及来源、对画面和旁白的影响、你的建议。等用户回答后再继续，并把决定写进运行记录。
