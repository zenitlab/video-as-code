# 流程（张良拾履实际走过的，含用户返工）

## 0. 先拆参照片（每条新参照片都从零拆）
只带方法和工具，不带上一条片子的风格规则。
1. 动态统计：`uv run --with numpy python scripts/motion.py 参照片.mp4`（帧差中位数、静止帧、硬切）。
2. 字幕换句和卡不卡拍：`scripts/subs.py` 存每帧亮像素数，`scripts/subphase.py` 算出字落在拍上的比例（和 0.25 比）。
3. 换场：`scripts/scenes.py` 找峰值，判断硬切还是叠化；再用 `scripts/sheet.py` 在换场处出 10fps 逐帧图看是什么转场。
4. 动作帧数：`scripts/sheet.py 参照片 起 时长 15 行 输出 5 784:441:88:3` 出 15fps 逐帧，数蓄力 / 动作 / 过冲 / 回稳各几帧。
5. 造型比例：抽一帧放大三倍（`ffmpeg … crop … scale=3x`）量头、身、手、脚。
6. 字幕：放大字幕区，**量字宽不要量字高**（张良拾履初稿按字高估成 54px，实际 68px，复盘才发现）。
7. 声音：`ffmpeg -lavfi showspectrumpic` 看动作处有没有拟音（D1 有：嗖、上滑、闷响）。
8. 镜头：`scripts/cam.py 参照片 起 时长` 测缩放和平移。
结论写进 `拆解/<参照片>/拆解结论.md`。

## 1. 选题和文案（先给用户确认）
- 适合这种风格的题材：**有重复挫败或连环动作**（三次赴约、挡三回、八根筷子），有具体可演的小动作（踢鞋、喷饭、踩脚），有反差结尾。
- 文案一句一行，标【】浅蓝、〔〕红，写清每句的画面和出处。
- **每件事都要有完整前因后果**（用户返工过一次）：不只写「做了什么」，还要写「为什么」和「结果」。故事可以短，但不能缺因果。例：借箸要说「筷子当算筹」「最要紧那条是什么」；踩脚要说「刘邦被围、正等韩信救」「现在拦不住不如顺着」。
- **人物生涯比例要匀**（用户返工过一次）：张良初稿前半段 140 秒、后半生 30 秒，被指出后补了 13 句计策。写人物片先列一生的大事，按时间分配篇幅。
- 原话：核实过的原句挂卷轴 + 白话字幕；白话不冒充原句。
- 用户字幕规矩：句中全角空格，句末不加标点；不改用户定的每句字数。

## 2. 开工
```bash
node <skill>/scripts/new_project.mjs <新文件夹> [配乐] [--example | --example=冯谖]
cd <新文件夹> && npm install
```
空白模板是 15 秒「门口挡三回」演示；`--example` 复制张良拾履全片当底子。

## 3. 15 秒样片
- 先做一个造型测试页（`test.html` + `test_chars.js`）对照原片放大图调比例。
- 再做开头 15 秒，出 `stills`，和原片同类动作逐帧并排（`scripts/cmp.py`），重点看三件事：**人够不够大**（D1 近景人占画面一半）、**动作幅度够不够**、**道具看不看得清**。张良样片第一版三条全中，改了构图、加大幅度、放大鞋并加残影。
- 拟音和 BGM 一起合进去给用户听。

## 4. 全片
- 一段一个场景函数，局部时间 `t = T - 起点`；镜头用 `camStd` 关键帧。
- 渲染：`node render.mjs video --out=名字 --crf=22`（250 秒约 13 分钟，放后台），再
  `uv run -q --with numpy --with scipy python -I audio/mix.py out/cues.json out/mix.wav audio/bgm.m4a`，
  `ffmpeg -i out/名字.mp4 -i out/mix.wav -c:v copy -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a aac -b:a 160k -shortest out/成片.mp4`。
- 每段先出 3–4 张截图检查：字幕会不会压到人头、气泡、弹字（三行字幕到 y≈380）。

## 5. 复盘
- 动态统计和原片并排（目标：帧差中位数和静止帧接近原片）。
- `cmp.py` 按同类手法对齐出三张对照图：动作、道具转场、场景。
- 写 `复盘.md`：对上了的、复盘改掉的、还不如原片的。

## 6. 封面和发布
- 封面复用片子引擎重新构图（例片 `cover/`）：竖版 1080×1440 **用 1920 宽画布画再从中间裁**（场景背景按 1920 铺，直接画 1080 宽会露接缝）。出三个方向 + 缩略图检查（240 / 320 宽看得清标题）。张良拾履用户选了 A「忍了」（全片钩子）。
- 标题、简介、话题、置顶评论写进工作区 `发布文案.md`；B 站简介按出处分条。提醒授权和 AI 标注。

## 重复段落要升级（冯谖片用户反馈）
同一个动作重复三回（弹剑唱三回、挡三回），**每回换场景、换机位、加新东西，一回比一回大**：冯谖第一回饭桌叹气 → 倚柱；第二回府门口被车扬尘扑脸、咳嗽 → 门柱；第三回站上长案、顶光、全场压暗、众人捂耳、声浪。三回用同一个机位，用户说「单调、不吸引人」。唱词 / 台词可以一个字一个字从嘴里飘出（`lyrics()`，屏幕坐标，末字红）。

## 拟音返工（冯谖片用户反馈）
先出旧新对比试听（`audio/试听/`），用户点头再换。合成人声笑不行 → 换真实录音；噪声拟音像气音 → 换有音高的卡通音效。只改声音时不用重渲画面：`node render.mjs stills 1` 重写 cues.json，再混音合到已有的无声片。

## 改稿加字幕（不重画旧场景）
用户要补内容时，旧场景可以不重写：把旧时间轴按新字幕分段线性拉伸（例片 `scenes_mid2.js` 的 `MAP` + `remap/unmap`），旧场景照旧调用、传进去换算后的时间，新内容在外面叠；拟音也按同一映射换算。代价是被拉长的段落动得少（张良拾履帧差中位数从 0.75 降到 0.69），拉得厉害的段落要补动作。
